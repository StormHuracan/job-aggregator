# Frontend Job Aggregator

Vue 3 + TypeScript + Vite. Зависимости устанавливаются через `npm ci`
из каталога `frontend/`.

## Локальный запуск

```bash
npm run dev -- --host 127.0.0.1
```

Vite доступен на `http://127.0.0.1:5173`. В `.env.example` задано
`VITE_API_BASE_URL=/api`. Без переменной используется то же значение.
Dev proxy направляет `/api/*` в FastAPI на `http://127.0.0.1:8000`, удаляя
префикс `/api`. Для production нужен аналогичный reverse proxy или заданный
при сборке `VITE_API_BASE_URL` и соответствующая настройка backend.

## API-контракты

`src/api/client.ts` отправляет cookie через `credentials: "include"`.
HTTP 401 сохраняет статус в `ApiError` для route guard; остальные HTTP и
сетевые ошибки имеют безопасные сообщения без тела ответа сервера.
Ответ 204 возвращает `undefined`; некорректный JSON успешного ответа отклоняется.
TypeScript-типы описывают контракт; runtime-валидация полей JSON не выполняется.

Модули:

- `user.ts`: `/me`, настройки, отметка прочитанных matches и logout (JA-67).
- `vacancies.ts`: фильтры и пагинация `/vacancies` (JA-39).
- `saved-searches.ts`: список, создание и изменение `is_enabled` (JA-38).
- `collection.ts`: inline-запуск сбора с `text`, `area`, `pages_limit` (JA-37).

Страница `/saved-searches` использует реальный backend API: загрузку списка,
создание и включение/выключение поисков. Для неё нужна действующая cookie-сессия;
при 401 открывается `/login`. Формы показывают безопасные ошибки валидации 422.
Страница `/vacancies` использует реальный API: поиск с фильтрами, общее количество
результатов и пагинацию. Параметры записываются в URL; навигация назад/вперёд
восстанавливает запрос. Отдельная раскрываемая форма запускает настоящий сбор
HH.ru с явными `text`, `area` (ID региона HH.ru) и `pages_limit`.

Router и личный кабинет используют реальный `GET /me`; demo fixture удалён.
Guard при 401 переводит на `/login` с исходным маршрутом в query. Кабинет загружает
публичный профиль, сохраняет настройки через `PATCH /me/settings`, отмечает
совпадения через `POST /me/matches/mark-seen` и завершает серверную сессию через
`POST /auth/logout`. После успешного logout профиль очищается; ошибки не заменяются
демонстрационными данными. Запоздавшие ответы после ухода со страницы игнорируются.

Для сквозного сценария backend должен предоставлять весь контракт JA-67:
`/me`, `/me/settings`, `/me/matches/mark-seen`, `/auth/logout`. На момент подключения
frontend этих endpoint-ов в main ещё нет: это реальная блокирующая зависимость,
а не повод добавлять фиктивный API. HTTP-подмены используются только в тестах.

Кнопка входа направляет на `${VITE_API_BASE_URL}/auth/hh/login`. Ветка JA-31
предоставляет callback с cookie и redirect `/account`; для реального OAuth нужны
credentials и зарегистрированный callback через origin frontend (например,
`http://127.0.0.1:5173/api/auth/hh/callback`). Ошибка callback по `?error=…`
отображается на экране входа.

Токены и session cookie приложение не читает, не сохраняет в web storage
и не выводит в console. OAuth session cookie управляет backend.

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

API-тесты подменяют только `fetch` и проверяют публичные функции адаптеров:
пути, методы, payload, cookie, сериализацию query-параметров и ошибки.

Component-тесты страницы поисков проходят через настоящий API-клиент с
подменой `fetch`: проверяют pending, 401, 422, повтор загрузки и изоляцию состояния.

## Дизайн-система

`src/styles/tokens.css` задаёт семантические цвета, шкалу отступов, радиусы и тени.
`global.css` содержит типографику, поля и общие классы `panel`, `field`, `page-heading`.
Шрифт — Manrope с кириллицей, локальные WOFF2 в `public/fonts` (лицензия OFL).
Внешние запросы к Google Fonts при работе приложения не выполняются.
Общие состояния: `UiButton`, `UiAlert`, `EmptyState` и `AsyncState`.
Формы используют нативные поля и семантические labels; тяжёлых UI-зависимостей нет.

На мобильном экране список сохранённых поисков предшествует раскрываемой форме.
Ошибки загрузки исключают пустое состояние и неподтверждённый счётчик результатов.
Сортировка вакансий соответствует API: новые публикации первыми; выбора другого
порядка, уведомлений и недоступных полей вакансий интерфейс не предлагает.
